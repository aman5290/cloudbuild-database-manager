# Coding Standards

---

# Purpose

Maintain a consistent coding style throughout the project.

---

# Python

- Use descriptive function names.
- Add docstrings to all public functions.
- Group related functions with section headers.
- Keep business logic out of templates.
- Use constants where appropriate.

---

# SQL

- One migration per responsibility.
- Never modify executed migrations.
- Use lowercase names.
- Use snake_case.

---

# HTML

- Extend base.html.
- Comment major sections.
- Keep templates presentation-only.

---

# CSS

- Organize by section.
- Reuse classes.
- Avoid duplicate styling.

---

# Git

Commit after each completed sprint.

Commit message format

V6 Sprint 6.1.3 - Query history page

---

# Documentation

Update

- Development Journal
- Feature Log
- Release Notes

after each completed feature.
